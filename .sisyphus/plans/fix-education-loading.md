# Work Plan: Optimize Education Menu Loading Performance

This plan addresses the slow loading issue in the Education menu by implementing a "Cache First" strategy, decoupling independent network requests, and introducing a global state management for education data.

## Problem Analysis
- **Blocking Waterfall**: `EducationScreen` waits for both `EducationService.getCategories()` and `UserService.getMyProfile()` to complete before rendering anything.
- **No Persistence**: `EducationService` does not cache results. Every navigation to the screen triggers a fresh network request over a high-latency Ngrok tunnel.
- **Sync UI Updates**: The UI remains in a blank "loading" state even if some data (like static categories) is available.

## Proposed Changes

### 1. Model & Service Layer
- **[NEW]** `lib/providers/education_provider.dart`: Manage education categories globally.
- **[UPDATE]** `lib/services/education_service.dart`: 
    - Implement `saveLocalCategories` and `getLocalCategories` using `SharedPreferences`.
    - Update `getCategories` to return local data if available.

### 2. State Management Layer
- **[UPDATE]** `lib/main.dart`: Register `EducationProvider`.

### 3. UI Layer
- **[UPDATE]** `lib/screens/education_screen.dart`:
    - Use `EducationProvider` to access categories.
    - Implement "Instan Load" by showing cached/static data immediately.
    - Decouple User Profile loading from Category loading.
